# RB-06: `FileSandbox` semantics, transactions, and rollback

- **Owner:** WS-11
- **Status:** not_started
- **Blocks:** ADR-0005 confidence, WS-05's batch executor, every atomic-batch claim
- **Priority:** highest — start immediately

## Why this is urgent

ADR-0005 builds all rollback on `UE::ToolsetRegistry::FGlobalSandbox`
(`Enter` / `GetChanges` / `Persist` / `Discard` / `DiscardFiles`)
`[VERIFIED: $TR/.../Public/ToolsetRegistry/SandboxLibrary.h]` plus the editor
transaction buffer via `UToolsetLibrary::UndoTransaction` / `GetActiveUndoCount`
`[VERIFIED: ToolsetLibrary.h]`.

The header tells us the API shape. It does not tell us the **semantics**, and the
semantics are what determine whether atomic multi-asset batching works at all.

Until questions 1 and 3 below are answered, **no workstream may claim atomic
multi-asset rollback works**, and `rollback.available` reports `false` in every
response (ADR-0005 verification).

## Questions

### A. Coverage — does the sandbox see what we do?

1. **Does `FileSandbox` intercept Unreal package saves** (`UPackage::Save`,
   `UEditorLoadingAndSavingUtils`, `FEditorFileUtils::PromptForCheckoutAndSave`), or
   only raw `IFileManager` writes? **If package saves are not intercepted, ADR-0005
   has a hole and needs rework.** This is the single most important question in the
   brief.
2. Does it cover asset *deletion*, or only creation and modification?
3. What happens to the **asset registry** and to in-memory `UObject`s after `Discard`?
   Are there stale objects pointing at discarded packages? Is a forced reload or an
   editor restart required to return to a clean state? A rollback that leaves the
   editor unusable is not a rollback.
4. How does Blueprint compilation interact? Is generated bytecode / CDO state discarded
   with the files, or does it survive in memory and diverge from what is on disk?
5. Does it cover files outside `Content/` — `Config/`, `Saved/`, generated source,
   external tool output?

### B. Lifecycle

6. **Can sandboxes nest?** What does `Enter` do while `IsActive()` returns true? A
   nested request must not silently join or clobber an outer sandbox.
7. What is the interaction with `Leave` vs `Persist` vs `Discard` — is `Leave` implicitly
   one of them?
8. What happens if the editor crashes with an active sandbox? Is there recovery, or is
   the project left in an indeterminate state? (Relevant to master prompt §18 crash
   recovery.)
9. Is the sandbox per-editor-session or persisted?
10. What does `FSandboxedFileChangeInfo` actually contain? ADR-0005 rule 4 derives the
    entire `changes` manifest from `GetChanges()`, so if it lacks e.g. the asset class
    or previous revision, the manifest needs supplementing.

### C. Transactions

11. How do editor transactions (`GEditor->BeginTransaction` / `FScopedTransaction`)
    compose with the sandbox? Does undo after `Persist` do something coherent?
12. Does `UndoTransaction` from a tool call risk undoing *user* actions rather than the
    agent's? This is a "silently destroys user work" hazard — treat it as such.
13. Are asset creation and Blueprint compilation transactable at all, or only property
    edits?

### D. Cost

14. What is the performance cost on a batch touching 100+ files? If sandboxing is
    expensive, `options.atomic` may need to default differently for large plans.
15. Does `dry_run` implemented as enter-execute-discard (ADR-0005 rule 5) have
    acceptable cost, given it does real work?

## Method

Empirical, in the editor. Suggested sequence:

1. `Enter`, create one asset, `GetChanges()`, inspect. `Discard`. Check disk **and**
   the asset registry **and** the content browser.
2. Repeat with a saved package, a compiled Blueprint, a deleted asset.
3. Attempt a nested `Enter`.
4. Force-fail mid-batch, discard, then attempt the same batch again — does the retry
   succeed cleanly? (This is `Idempotency.RepeatedCreate` interacting with rollback.)

Record exact code and output for every `[VERIFIED-RUNTIME]` claim.
