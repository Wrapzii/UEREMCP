## Executive summary

Wave 2 on orch is real scaffolding, not vapor: uplugin lists nine modules including
Material + EditorToolset; Validation automation sources cover rollback / idempotency /
revision; Transport C++ automation exists; Material/Niagara stubs return honest
`partially_completed`; Security policy + dry-run force land with unit tests; Templates
Python suite is green.

What is **newly wrong** is composition and evidence hygiene:

1. **Critical:** Material, Niagara, and Templates toolsets never call
   `UToolsetRegistry::RegisterToolsetClass` — modules load, MCP cannot see them.
   Only Core + Blueprint register today.
2. **High:** Validation **6/6** and Transport **5 PASS / 3 SKIP** cite raw logs that
   are **not on orch**; orch’s committed Validation redaction still shows **5/6 FAIL**.
   Sibling worktrees hold the SUCCESS logs; critic verified them this session.
3. **High:** Idempotency/Revision “PASS” is a **protocol + CurveFloat scratch harness**,
   not a domain pipeline — orch/ADR branding as the ADR-0006 gate outruns the harness
   comments.

**Orch readiness verdict:** Do **not** treat Wave 2 domain surfaces as MCP-reachable.
Authorize continued scaffold work; block any claim that Material/Niagara/Templates are
agent-callable until registration mirrors Blueprint.

## Findings by severity

### Critical

#### C-1. Wave 2 domain toolsets are not registered with ToolsetRegistry

`UToolsetRegistry::RegisterToolsetClass` appears only under:

- `UeremcpCore/Private/UeremcpCoreModule.cpp` (ReferenceToolset)
- `UeremcpBlueprint/Private/UeremcpBlueprintModule.cpp` (PostEngineInit)

**No matches** in `UeremcpMaterial/**`, `UeremcpNiagara/**`, `UeremcpTemplates/**`, or
`UeremcpSecurity/**`.

Evidence:

| Module | uplugin @ `a28888b` | `RegisterToolsetClass` | Agent-visible? |
|---|---|---|---|
| Blueprint | yes | yes (`UeremcpBlueprintModule.cpp:44`) | yes (Ping/Echo) |
| Material | yes (`a28888b`) | **no** (`UeremcpMaterialModule.cpp` log-only) | **no** |
| Niagara | yes | **no** (log-only module) | **no** |
| Templates | yes | **no** (store loads; toolset never registered) | **no** |

WS-08’s own proposal (`docs/proposals/ws-08-register-material-module.md` lines 48–50)
defers “auto-discovery vs explicit `RegisterToolset`” — that is the defect, not a
follow-up nicety. ADR-0002 / Core pattern requires explicit registration
`[VERIFIED: UeremcpBlueprintModule.cpp:44]` / `[VERIFIED: UeremcpCoreModule.cpp]`.

**Impact:** Orch tip can truthfully say “Material module registered in uplugin” while
still delivering **zero** Material/Niagara/Templates tools on `list_toolsets`.

**Required action:** Domain owners (WS-08/07/15) register toolsets on PostEngineInit
mirroring Blueprint; WS-03 confirm load order. Until then, docs must say
“compile/load only — not MCP-registered.”

**Owner:** WS-08, WS-07, WS-15 (impl); WS-03 (uplugin/load review).

`docs/proposals/ws-14-ws07-register-niagara-toolset.md`,

#### H-2. Idempotency / Revision PASS overstates ADR-0006 domain readiness

`IdempotencyRepeatedCreate.spec.cpp` lines 61–64 / 221–223: harness is explicitly
“protocol harness; not full domain pipeline.” Runtime AddInfo from the SUCCESS log:

```
statuses: created_and_validated | created_and_validated | created_and_validated
(protocol harness; not full domain pipeline)
```

Repeats pass because `TryGetReplay` + `metrics.replayed` keep the **stored** status
string (`created_and_validated`), not because `no_change_required` was computed from
domain equality. `Revision.StaleRejected` log line likewise: “protocol+scratch harness
… full graph pipeline not wired.”

Orch/ADR “Verification” / R-03 “Validation 6/6” branding invites readers to treat POC
E3/E4 and ADR-0006 as closed for Blueprint/Niagara. They are **not**.

**Required action:** Narrow ADR-0006 runtime note and RISK_REGISTER wording to
“protocol + scratch CurveFloat harness”; keep E3/E4 open until a domain path is wired.

**Owner:** WS-01 (docs), WS-11 (test naming/summary), WS-05 (idempotency product path).  
Proposal: `docs/proposals/ws-14-ws01-validation-6of6-scope.md`.
