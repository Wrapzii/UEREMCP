## Executive summary

Wave 1 delivers strong research and protocol scaffolding (WS-02 source audit, WS-04
transport handoff, WS-05 envelope/hash/ref/topo in C++ + Python, WS-11 rollback
probe). It does **not** yet satisfy the Wave 1 gate in `docs/WORK_ALLOCATION.md`:
**WS-03 has shipped zero commits** — there is no compiling `UToolsetDefinition` with
an `AICallable` tool reachable from MCP, and `UEREMCP.uplugin` on `main` registers
only `UeremcpCore` + `UeremcpProtocol` with no validation module.

Cross-cutting risks for Wave 2:

1. **Tests exercise Python mirrors, not production C++** (WS-05) or duplicated probe
   copies (WS-11).
2. **`rollback.available` / ADR-0005 "PASSING"** rest on editor runs via a **probe
   plugin** with `UEREMCP` disabled — not the shipping plugin graph.
3. **WS-02 audit status overstates completion** while runtime enumeration failed and
   `reagenttools.md` remains `in_progress`.
4. **`ws-01-orch` is a shared integration lane** with interleaved WS-02/04/05/11
   commits; `check_ownership.py --ws WS-01` flags 100+ foreign paths.

**Verdict:** Partial completion — honest about several limitations, but several
handoff artifacts are claimed ahead of evidence. Wave 2 (POC A) must not start until
WS-03 lands and C++/editor test parity is closed.

## Findings by severity

### Critical — blocks Wave 2 / downstream claims

#### C-1. WS-03 Wave 1 deliverable absent

`ws-03-plugin` has **no commits beyond `main`** (`a7aaf04`). `UEREMCP.uplugin` still
lists only `UeremcpCore` and `UeremcpProtocol`; no `UeremcpValidation`, no reference
`AICallable` toolset proving ADR-0002.

`tests/run_editor_tests.ps1` line 14–17 documents the blocker: editor aborts when
`UEREMCP` is enabled but `UeremcpCore` is not built.

**Action:** WS-03 must land before any workstream treats the plugin as loadable.
See `docs/proposals/ws-14-ws03-wave1-blocker.md`.

#### C-2. WS-05 protocol tests do not exercise C++ production code

`Plugins/UEREMCP/Source/UeremcpProtocol/Tests/README.md` lines 21–22 state C++
"must match" Python, but:

- All 32 tests run via `Tests/py/run_tests.py` against `ueremcp_protocol/` only.
- **Zero** `IMPLEMENT_*_AUTOMATION_TEST` or C++ unit tests in `UeremcpProtocol`.
- `CONTENT_HASH.md` lines 66–67 claim byte-identical C++/Python output with no golden
  vector bridging them.

Handoff in `WORK_ALLOCATION.md` requires **envelope round-trip in C++**; the C++
implementations exist (`UeremcpEnvelope.cpp`, etc.) but parity is **unverified**.

**Action:** `docs/proposals/ws-14-ws05-cpp-parity-golden-vectors.md`.

#### C-3. Rollback gate runs through probe plugin, not shipping module graph

`tests/integration/Rollback.MultiAssetDiscard.md` lines 39–41: green result observed
with `UeremcpValidationProbe` and `-DisablePlugins=UEREMCP`.

ADR-0005 (`docs/adr/ADR-0005-transactions-rollback.md` lines 117–119) now records
**PASSING** and permits `rollback.available: true` for a scoped path — but
`UeremcpValidation` is **not registered** in `UEREMCP.uplugin` (proposal accepted
by WS-01, assigned to WS-03, not implemented).

Duplicate sources:

- `Plugins/UEREMCP/Source/UeremcpValidation/Private/Tests/RollbackMultiAssetDiscard.spec.cpp`
- `tests/integration/editor_plugin/.../RollbackMultiAssetDiscard.spec.cpp` (identical
  327-line copy)

**Risk:** Probe and main module drift; ADR claims rest on non-shipping build graph.

**Action:** `docs/proposals/ws-14-ws11-probe-plugin-drift.md`.
