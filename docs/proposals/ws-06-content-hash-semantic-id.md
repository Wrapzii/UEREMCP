# WS-06 → WS-05: `content_hash` / `semantic_id` for Blueprint graphs

- **From:** WS-06
- **To:** WS-05 (protocol / hashing)
- **Date:** 2026-07-29
- **Refs:** ADR-0004, ADR-0006, RB-05 q13–q15

## Ask

Please implement `content_hash` (and document `revision` relationship) using the
**structured canonical form** below — **not** Epic DSL text.

## Why DSL hashing fails

`[VERIFIED-RUNTIME: RB-05]`

- Decompiler **elides** `(bind loc …)` into inlined pure calls.
- Switch decompile may reorder case labels vs input DSL.
- Positions and engine node paths churn on rewrite.

Identical *logic* therefore does not imply identical DSL strings in all cases;
conversely, DSL-identical round-trips we observed are necessary but not sufficient
as the hash contract.

## Canonical hash input (v1 proposal)

UTF-8 JSON, `sort_keys=True`, no positions/GUIDs/`refPath`/retrieval-local ids.

```json
{
  "schema_version": "1.0",
  "graph_type": "BlueprintEventGraph",
  "graph_name": "EventGraph",
  "variables": [ /* sorted by name; include replication fields */ ],
  "nodes": [
    {
      "semantic_id": "EventGraph/event:EventBeginPlay/n003:Development|PrintString",
      "type_id": "Development|PrintString",
      "properties": {},
      "pin_defaults": { "InString": "hello", "Duration": "2.0" }
    }
  ],
  "links": [
    {
      "from": "…/n002:…",
      "from_pin": "then",
      "to": "…/n003:…",
      "to_pin": "execute"
    }
  ]
}
```

Links sorted lexicographically. Omit pin defaults equal to autogenerated defaults
when detectable.

## `semantic_id` algorithm (WS-06 will implement in Blueprint module)

```
{graph_name}/{entry_kind}:{entry_name}/n{topo_index}:{type_id}[#{qual}]
```

- Topo order: deterministic BFS/DFS from each entry; pure nodes ordered by
  dependency then `type_id` then pin-default fingerprint.
- `qual` = function path / custom event name / timeline name on collisions.

## Revision

Recommend `revision == content_hash` for v1 (content-addressed) unless WS-05 needs
a separate monotonic counter for non-graph assets.

## Tests WS-05 can add without editor

- Golden JSON → hash stable under key reorder.
- Fixture with/without `position` fields → same hash.
- Fixture differing only in `InString` default → different hash.
